# ISO9660 Support in Cupid OS

Cupid OS mounts `.iso` files as read-only ECMA-119 filesystems. Rock Ridge
`NM` records provide long display names.

## Quick start

1. Run `make sync-iso` on the host. Hostbuild freezes the members pinned by
   `test_iso/fixtures.manifest`, asks checked CupidObj to build
   `test_iso/hello.iso`, verifies those bytes independently, then copies the
   image into FAT16 as `/hello.iso`. No external ISO utility is needed.
2. Boot Cupid OS with `make run`.
3. Run `mount /disk/hello.iso /iso` in the shell.
4. `ls /iso` lists `big.bin`, `gen_big.sh`, `jpeg_baseline_8x8.jpg`,
   `long_named_file.txt`, `readme.txt`, and `sub/`.
5. `cat /iso/readme.txt` prints the fixture text.
6. Run `umount /iso` when finished.

## Features

- ECMA-119 base identifiers use sorted uppercase 8.3 names and `;1` file
  versions. An extensionless file keeps the required empty extension, for
  example `README.;1`.
- Rock Ridge `NM` records provide long names. The reader follows bounded SUSP
  `CE` chains.
- Path lookup is ASCII case-insensitive, so `/iso/README.TXT` matches
  `readme.txt`. Directory listings keep the original case.
- Up to four ISO files may be mounted at once.
- VFS supports read, stat, seek, and directory iteration.

Checked CupidObj emits both path-table byte orders, fixed UTC metadata,
and the older `RRIP_1991A` profile used by the tracked fixture. Its one `CE`
continuation follows the complete directory stream, and it omits the optional
`ST` field just as the previous xorriso fixture did. Sequential host readers
therefore keep processing every `NM` long name. `PX` and `TF` records help
other readers, but Cupid OS ignores them. The writer rejects undeclared or
missing fixture members, links and Windows reparse points, special files,
names outside the portable letter, digit, dot, underscore, and dash alphabet,
case-only name collisions, names beyond the guest's 127-byte directory limit,
a ninth directory level, and input changes during authoring.
Rebuilding unchanged input keeps the existing image and timestamp.

The normal recipe runs `cupidobj iso-fixture` from the checked seed. The
command takes the ASCII manifest plus an explicit inventory of logical
directories and privately loaded files, and it matches the tracked image
exactly. Python then renders the same snapshot independently, rechecks live
inputs, and publishes under a per-output lock. ADR 0240 records carriage in
the checked seed, and ADR 0241 records the production handoff.

## Limitations

- The filesystem is read-only. Write, create, and unlink return
  `-VFS_EACCES`.
- There is no ATAPI driver. The source must be an ISO file already available
  through VFS, such as `/disk/hello.iso`.
- Joliet is not supported. Unicode-only images fall back to base ISO names.
- Rock Ridge `SL` symlink records are ignored.
- Deep-tree relocation through `CL`, `PL`, or `RE` records is not supported.
  The repository writer lays its small fixture tree out directly and rejects
  a primary hierarchy deeper than eight directory levels.
- ECMA-119's 32-bit data length limits files to 4 GiB.

## Architecture

```text
shell mount
  -> VFS mount
    -> ISO9660 VFS adapter (four-slot pool)
      -> PVD, directory, and SUSP reader
        -> file-backed loop device
          -> block cache
            -> VFS read on the ISO file
```

The reader lives in `kernel/fs/iso9660.cc` and
`kernel/fs/iso9660_vfs.cc`. `kernel/fs/loopdev.cc` supplies the file-backed
block device. Checked-seed CupidObj owns the production ISO bytes.
`tools/hostbuild.py` freezes and validates host paths, renders the independent
oracle, checks for drift, and publishes atomically. ADR 0239 records the source
boundary, ADR 0240 records seed carriage, and ADR 0241 records the normal
output transfer.

## Testing

- `test_iso/fixtures/` is the checked-in source tree.
- `test_iso/fixtures.manifest` is its exact build membership.
- `test_iso/hello.iso` is the byte-reproducible tracked image.
- `make sync-iso` rebuilds the image and copies it into the FAT partition.
- `python -m unittest tests.test_hostbuild.HostBuildIsoTests` checks the
  guarded publisher without calling `mkisofs`, `genisoimage`, or `xorrisofs`.
- `python -m unittest tests.test_toolchain_cupidobj` checks the CupidObj
  command against the exact tracked image, reversed entry order, and useful
  failure paths.
- `python -m unittest tests.test_toolchain_bootstrap_seed` checks direct seed
  carriage, exact image bytes, fixed-point behavior, and preserved output on
  failure.
- The build-graph audit records the ISO with `cupid_object` and `host_python`
  participants. CupidObj owns 189 transforms, and every root output has a
  Cupid tool owner. No root output is Python-only. ADR 0244 records the Doom
  profile-manifest handoff that completes this ownership count.
- `bin/feature17_iso.cc` is the end-to-end guest test. It enumerates the
  exact six root names before checking lookup, content, JPEG decoding, and
  mount-pool behavior.

The ADR 0241 production-handoff build completed in 502.232 seconds and produced a
209,715,200-byte image with SHA-256
`3f8c84cea61e5e8bfc4e6a5fc09a030a4d6451d258a4ca2ea6486a923d1d08e3`.
Its private four-vCPU e1000 frontier passed in 496.479 seconds and reached the
six-name listing, `PASS feature17_iso`, and CupidC JIT completion.

Run `cc /bin/feature17_iso.cc` in Cupid OS and expect
`PASS feature17_readdir names=6 long=long_named_file.txt`, followed by
`PASS feature17_iso`.
