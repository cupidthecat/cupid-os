# Private retained image publisher

Sixteen native and Cupid-built cases pass on Windows and Linux. The private
caller runs the actual checked CupidObj, transfers its accepted template into
frozen input custody, composes a complete 200 MiB candidate through the existing
C disk renderer, finishes the owned store and publishes it through retained
guards. This connects the previously separate producer, range and store checks.

Four source caches read validated blocks of at most 64 KiB. The sector sink
checks contiguous order and combines 409,600 sector callbacks into 3,200 bounded
store writes. Final publication keeps complete input validation. The private
adapter, header and three includes remain identical to the accepted range
version. Both checked callers use the qualified composer's exact object bytes.

## Complete images and rejection

Twelve positive cases cover reuse, formatting and an absent previous image.
Reuse preserves the previous FAT suffix and reproduces the currently booted
image at 209,715,200 bytes, SHA-256
`06f5996c06ec5da1c027bafa22fb6511d3e011fe6ffa9f40d3bdd1bd081b57ff`.
The kernel has 9,416,096 bytes. Formatting and missing-image cases match the
independent Python author, including the complete zero data area.

Four wrong-template cases use a real checked template for different geometry.
The renderer rejects it before its first candidate write. Publication fails and
the original public bytes, identity and modification time remain unchanged.

Independent review replays each actual native-format CupidObj under the original
60-second producer bound. Both prefixes match the Python author. It also checks
every byte of the retained canonical image prefixes, FAT suffixes and pristine
data, plus all source/program guards and runtime records. Caller cases retain
18,000 seconds; Linux retains 32 MiB and 10,240 descriptors.

Runtime output copies are retired after complete observer hash and block
comparisons. Review verifies those retirement records and retained canonical
images; it does not claim a later reread of removed output copies.

## Scope and retained evidence

correctly fails input capture. Copying the exact original bytes into that fixture
corrects its setup without changing the C caller or adapter. Arbitrary external
inputs, complete file staging, active ABI/source-plan integration, qualification
and the normal image-command/Make handoff remain open. Installed seeds and the
three Python-coordinated transforms are unchanged.
