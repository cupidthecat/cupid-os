# Publish required files through the checked disk template

The separate `cupidbuild_disk_publish` module connects paired producer capture,
retained payloads, UTF-8 destination projection, complete image composition,
FAT16 staging, independent content validation and guarded publication. Its
caller supplies the existing wide transaction and same-root observer, along
with an authorized paired release and a complete required-file request.

Project every destination before executing the producer. Capture the checked
CupidObj template and every payload before opening the native store. Copy each
registered pathname before input-table growth can invalidate its borrowed
spelling. A repeated identical live payload path reuses its first capture;
a payload equal to the requested kernel uses the retained kernel capture.
Callers may explicitly supply already registered inputs, including the boot
capture. Other physical aliases retain the host adapter's rejection rules.

Stage all requests in order. Projected destination collisions keep sequential
replacement; the final expected table contains the last payload at each
destination. Earlier captures remain subject to complete input revalidation.
Close the FAT writer, finish and hash the owned candidate, then independently
check its complete prefix, geometry and final payloads through a read-only
store. The guarded host publication call owns the complete input, candidate
and publication-boundary checks. Its equal-image path also rechecks the public
binding before returning.
Equal complete images keep their public timestamp.

Failure clears the result and requires discarding the operation. The module
closes its temporary writer, bridge and file tables. The caller still closes
the transaction before its observer and checks both cleanup results. Host
publication recovery applies after namespace interference; the API does not
promise rollback in that case.

## Bounds and ownership

The image and candidate use the existing full-width retained interfaces. The
checked producer keeps its 60-second runtime and 64 MiB private-output limit.
Each payload retains FAT16's unsigned 32-bit file-size bound. The writer keeps
its existing first-directory-cluster capacity. No complete image or payload is
allocated by the module.

Optional discovery and absence observations belong to the caller. The normal
CLI, Make handoff, complete producer qualification and replacement seed adoption
remain open. The normal disk recipe is still Python-owned. This module does
not establish complete publication for every accepted large-image geometry.
