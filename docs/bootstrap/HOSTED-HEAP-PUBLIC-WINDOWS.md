## The original failure and its cause

The first complete Windows selection finishes in 2,300.548 seconds. Its native
boundary method passes, while the full fixed-point method rejects the expected
`host_execution` dictionary. The bootstrap report itself passes. Only CupidLD's
runtime-contract output size and SHA-256 differ:

| Runtime-contract image | Bytes | SHA-256 |
| --- | ---: | --- |
| Original expected image | 38,400 | `ea4cc776436b0a9bbbaeb6ad9728aee38ade8f793184bb05b8888bd60f71047a` |
| Current checked image | 41,472 | `5c11befc7b7df2d1907a16f2043725e7b74bd5ce41e97803b1ca277d97444a00` |

Replaying that same assertion twice against the retained report reproduces the
two differences. A direct checked-tool probe relinks the original start,
runtime-contract and current runtime objects. Ordinary and reversed import
arguments produce the same complete 41,472-byte image. It equals the qualified
runtime-contract image and both complete public behavior generations.

Compiling only the preceding `acbbd834` shared runtime and substituting that
one object recovers the exact former 38,400-byte image and its original hash.
Four strict checks pass. The new heap implementation accounts for the byte
change; no linker, import or runtime-output behavior is dropped. Only those
two stale expected literals change in the public test.

The earlier diagnostic failures remain retained: importing the root reader
selects old pins; the first import argument lacks the required `slot=` syntax;
and compiling the old runtime without its original `--gnu` setting rejects a
variadic builtin. The corrected probe follows the actual consumer recipe.
