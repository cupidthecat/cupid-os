# Optional source-file owners

The held source-file owner can select a regular input or retain a missing
suffix beneath its nearest existing parent. It copies the lexical request,
resolved parent and complete logical suffix while retaining the original
parent binding. Its five-field view and required-file API remain unchanged.
The implementation stays outside the normal 99-input producer closure.
Complete native image discovery and publication remain open.

The [evidence](evidence/native-source-optional-20261010.json) binds the combined
patch, all seventeen source files, both original builds and complete repository
replays. The [original archive](evidence/native-source-optional-originals-20261010.json.gz)
retains all source generations, complete receipts and failed approaches. The
[replay archive](evidence/native-source-optional-replays-20261010.json.gz)
retains every fresh command, child receipt and verification script.

## Selection and lifetime

`cupidbuild_source_file_open_optional_quota` requires owner and kind outputs.
Success returns `FILE` or `NONE`; failure clears the owner and reports `NONE`.
Zero, `SIZE_MAX` and insufficient quotas reject. Lexical and joined physical
paths retain their 8,191-byte bound. Directory, linked and special leaves
reject. Parent aliases resolve through the existing directory resolver.

For a missing `new/subtree/payload.bin`, selection retains the first absent
component and the entire suffix beneath the nearest existing directory.
Later appearance, disappearance or original-parent rebinding poisons the
owner. POSIX backslash remains a literal filename byte. Windows suffix
separators normalize to `/`. Volume roots, ordinary UNC share roots, Unicode
parents and POSIX double-slash roots have actual filesystem controls.

Views expose borrowed names and an observer after revalidation. The owner must
outlive every borrowing transaction. Metadata alone accepts restored-time
payload edits; retained streaming adds the digest custody needed to reject
them. Missing inputs cannot be streamed as regular files.

Optional validation uses the new
`cupidbuild_host_observer_require_source_unchanged` entry point. It verifies
the root's directory identity and original binding, all observed descendants,
first absences, streamed payloads and any captured membership. An unrelated
write in the selected parent passes until membership was captured. The existing
ordinary validation API still checks complete root metadata. Required-file
views retain that stricter contract.

## Failed approaches and compatibility limits

The first Windows UNC share-root oracle assumes a trailing slash. The actual
resolver returns `//localhost/C$`; an independent filesystem identity check
confirms that root. Only the share-anchor rendering expectation changes.

The first sibling-write control exposes the existing root-metadata difference
between ordinary validation and borrowed source validation. The separate source
validation entry point repairs optional construction and views while preserving
required-file and captured-membership rejections.

An initial Windows checked host rebuild omits the production Windows defines.
Linking then reports unresolved Linux syscall symbols. The corrected builder
uses the actual manifest's host source row, including GNU mode and `_WIN32=1`.
Source, imports and runtime bounds do not change.

The first full Windows UNC absence selection times out in its final appearance
case after retaining all 4,096 directories. Four unchanged-capacity controls
pass with old/new and native/Cupid callers, and the entire original selection
passes on retry. The failure's cause remains unproven. Its complete receipt and
all controls remain archived; no timing ratio is claimed.

Eight additional Python boundary calls expose differences that native image
integration still must resolve. Python treats a child of a broken parent alias
as missing on both hosts. Windows Python also treats a child of a regular-file
parent as missing; Linux Python rejects that case. The held owner rejects both
parent forms. The first diagnostic incorrectly expects both Python hosts to
reject a regular-file parent; its failed receipt is retained. These controls
do not establish complete Python discovery compatibility.
