## Retained input names

`cupidbuild_host_observer_open_source_quota` selects the source name profile
once, during construction. On POSIX it accepts literal colon and backslash
bytes within a strictly decoded UTF-8 component. Existing scalar checks, slash
separation, empty/dot/parent rejection and the 1,023-byte component and
8,191-byte path bounds remain. Windows delegates to the unchanged ordinary
name validator. The opaque owner carries the profile; entries do not duplicate
it or select a new policy during later checks.

Every retained-name consumer uses that profile, including complete optional
suffix preflight, directory enumeration and expected-member comparison. Invalid
capture requests poison the observer and clear supplied results. The operation
retains existing quotas, first absences, no-follow parent custody and payload
digest checks. It grants no output or release authority.

This closes a name-policy mismatch with the original image command. It does
not implement physical pathname selection or original-request custody. Wider
CLI filename/namespace behavior, complete input ownership and publication still
need integration; the lexical [source spelling component](NATIVE-SOURCE-PATHS.md)
is a separate prerequisite. Linked parents, special files and linked leaves
still reject in the observer itself.
