each raw and linked kernel. Both hosts independently produce these sizes:

The ELF writable segment grows by 616 bytes. Its subsequent BSS placement
and section table cross the 4,096-byte alignment boundary. Code and the
preceding read-only segment retain their complete header measurements.
Only these three exact policy rows change. The twelve tool rows and five
boot sectors retain their original exact sizes.

The copied first harness assumes that only the raw-kernel row can change.
Both kernel builds finish, and the preceding policy rejects all three
new sizes. The harness then fails at the linked ELF assertion before
writing the policy. The correction keeps those completed builds and logs,
measures all three rows and runs the complete normal build. The first
read-only layout check also assumes four program headers; inspection shows
six. Its corrected check uses the actual writable-data and BSS rows.

The first paired checker also omits `sys.modules` registration for its
`importlib` smoke validator. Python `dataclass` processing fails before
any review result is written. The failed checker and reproduced log remain
archived. Registering the module repairs that import while retaining every
product, command, source and runtime predicate.
