## Selection lifetime and publication boundary

`cupidbuild_host_observer_resolve_source_selection_quota` retains its first
resolved parent handle and original request. It validates that selection before
returning. `cupidbuild_host_observer_begin_source_selection_quota` instead lets
the caller capture the leaf before the same complete source validation. The
begin result must not be consumed before that validation.

Required-file, optional-file and image-stage selection constructors use this
temporary observer. Their combined `open_selection_view_quota` variants return
the first borrowed view at the successful constructor's validation point.
They require a result pointer and clear supplied owner, kind and view outputs
on failure. Existing view methods retain their complete validation, borrowed
lifetime and permanent rejection rules. A present-to-missing race during stage
construction rejects and clears the view.

Every selection observer has a publication restriction. Transaction borrowing
rejects it permanently, even when its selected file and metadata remain valid.
The caller must compare its captured file and parent with a complete retained
observer, and validate that complete observer before and after use. Ordinary
source-root, required-file and optional-file constructors keep their existing
physical-ancestor custody and publication contracts.

## Captured bindings and original requests

`cupidbuild_host_observer_file_parents_captured_same` compares the historical
parent identities of two retained regular files. The combined
`cupidbuild_host_observer_file_bindings_captured_same` compares both parent and
file identities with one lookup per observer. Neither function observes a new
path or validates metadata or payloads. Invalid, unobserved or poisoned inputs
clear the result and poison both supplied observers. Historical identity
equality can survive metadata drift; complete validation must still reject it.

`cupidbuild_host_observer_require_file_request_binding` reselects an original
absolute request against an already retained file. It resolves the physical
parent, compares its identity, opens the regular leaf without following links,
and checks the captured file metadata. It then resolves the original parent
again and repeats the parent and file checks before closing temporary handles.
Required inputs check complete parent metadata. Optional stages check parent
identity, so an uncaptured sibling may change. Both require the recorded
physical parent name and the same regular leaf.

This request check adds no observations and grants no publication authority.
It rejects unavailable paths, links, replacement, changed metadata and an alias
rebound to another parent even when that parent contains a hardlink to the same
file. Complete observer validation, including retained payload digests, must
bracket its use. Failure permanently poisons the observer.
