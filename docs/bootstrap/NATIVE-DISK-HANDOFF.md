## Bounded FAT16 staging, 2026-10-06

`toolchain/fat16_stage.cc` implements file staging over synchronous 512-byte
sector callbacks. A separate payload reader supplies bounded byte ranges.
Opening a volume retains one small allocator-owned handle; staging uses sector
buffers rather than complete image or payload buffers. The caller owns the
store and its exclusive private-candidate lifetime.

The writer validates the BPB, represented FAT16 cluster count, FAT capacity
and complete store extent before allocating its handle. It honors reserved
FAT shutdown/error flags, compares all FAT copies on access, skips padding
and reserved cluster numbers, and selects the lowest available data cluster.
New clusters are zeroed. Empty files use cluster zero. Replacements check the
complete old chain for invalid entries and cycles before freeing it.

The request supplies already projected 8.3 guest components. The writer creates
parents, writes dot and dot-dot entries, replaces ordinary files and preserves
unrelated directory bytes. It rejects a parent file, invalid directory cluster,
directory-to-file replacement, volume-label replacement and malformed names.
Root capacity and first-cluster directory capacity match the existing hosted
stage writer. The caller supplies captured sources and projected guest names.

An error after an attempted write invalidates the handle. The store may contain
partial changes, so that candidate must be discarded. Read failures before any
write leave the handle usable; tests check recovery through the same interface.
Closing releases the handle without closing the caller's store. This operation
does not flush, certify or publish a disk image.

The hosted i386 runtime now supports read/write, truncating read/write and
append read/write modes. It accepts `r+`, `rb+`, `r+b` and their `w` and `a`
equivalents. Invalid syntax fails before opening a path. The Windows adapter
requests both access rights and appends each write even after a seek. The Linux
adapter uses `O_RDWR` and the existing create, truncate and append flags.

## Guest-name projection

`toolchain/fat16_names.cc` projects UTF-8 components and complete absolute guest
destinations into those padded 8.3 names. It preserves the existing final-dot
split, uppercase expansion, character filtering, long-stem `~1` rule and
extension truncation. It validates the complete destination before changing
output. A count query lets the caller allocate enough names; insufficient
capacity reports the required count without returning partial names. Repeated
and trailing separators are ignored. A 1,025-component destination passes.

The request explicitly selects Unicode 15.0.0 or 16.0.0. These are the actual
Linux and Windows Python oracle profiles captured for this checkpoint.
Their tables contain 779 and 802 inclusive transform ranges. Surviving
non-ASCII letters are represented internally until filtering and truncation
finish, then rejected if they remain in the final name. This preserves cases
such as `straße.bin` becoming `STRASSE BIN`, discarded emoji, and a non-ASCII
letter removed by the long-stem rule. Malformed UTF-8 and embedded NUL fail.

Unicode profile selection is observable: U+1C89 disappears under Unicode 15,
but survives uppercase/filtering under 16 and can make a name unrepresentable.
The profile must therefore travel with the captured stage request. The native
publisher has not yet defined that request or selected a production profile.
Adding a later Unicode profile requires new captured transforms and contracts.

## Private image composition

`toolchain/disk_image.cc` composes a candidate through sector writes and captured
source views with 64-bit byte lengths and offsets. It uses fixed sector buffers
without an allocator. Before the first candidate write, an independent renderer
compares every checked-template byte with the bootloader, kernel, MBR, FAT16 BPB,
initial FAT copies, empty root and zero padding.

The reuse predicate keeps the existing publisher's exact size, partition and
BPB geometry rules. A valid previous image supplies every sector from the FAT
start onward. A missing, invalid or force-formatted image receives the complete
pristine template and a zero data area. A shorter replacement kernel also clears
the remaining prefix. The result reports whether any write was attempted;
failures after that point require discarding the private candidate.

Sources must stay captured and stable throughout the call. The composer does
not resolve host paths, retain live handles, flush, certify a staged filesystem
or publish an output. The current stdio test adapter covers offsets below two
GiB; the source interface itself retains 64-bit lengths and rejects kernel
overlap without truncating those values. Large-offset host adapters remain open.
