# Cupid Toolchain capability matrix

The matrix uses these statuses:

- **Observed**: the implementation is present in source and at least one relevant smoke was executed.
- **Partial**: useful implementation exists, but the required active-source or format coverage is not proven.
- **Missing**: no implementation satisfying the bootstrap contract was found.
- **Required**: the checked active-source audit proves the capability is exercised, but the Cupid implementation does not yet satisfy it.

The capability requirements below are backed by `ACTIVE-SOURCE-AUDIT.md` and `audits/active-build.json`: 698 active language inputs across root, user, and hosted toolchain build roots, 253 stable feature IDs, 504 output transforms, and an explicit i386 ILP32/cdecl/ELF32 contract. The language split is 27 assembly files, 105 C translation units, 270 C headers, and 296 Cupid C files. Lexical counts are discovery evidence; semantic completion still requires focused compiler and assembler tests.

The active-object audit finds 461 existing object paths. Of those, 428 are
i386 ELF32 objects inside CupidDis's contract and 33 are native hosted COFF
objects outside it. CupidDis accepts all 428 ELF objects, including 41,977
`R_386_32` or `R_386_PC32` relocations and 15,182 local, global, or weak
symbols. The 149 normal CupidC-owned objects, checked tool images, user
objects and executables, ISR, and context-switch objects decode without a
true `db` fallback.

The last complete instruction-gap census predates ADR 0123. It found 4,164
logical instructions across 54 mnemonics in 108 host-compiled kernel and Doom
objects. Padding NOPs accounted for 2,551, packed integer SSE2 for 1,066, and
three-operand immediate `IMUL` for 391. The immediate multiply encoding is now
represented. A current focused LLVM census found seven real instances in
`kernel/gfx/jpeg.o`, eighteen in `kernel/audio/nuked_opl3.o`, two in
`kernel/doom/src/r_main.o`, and none in `kernel/doom/src/m_fixed.o`. Across
those four host-built objects, CupidDis fallback rows fell from 540 to 495.
That sample does not replace the complete census. The safest next slices are
ordinary `66 90` and `0F 1F /0` padding, a narrow decode-only exception for
repeated-prefix Clang padding, and packed integer SSE2. Raw boot and trampoline
code bytes are covered when decoding starts at their real code boundaries.
Their mode maps still need an explicit code/data range kind so tables cannot
consume later code.
