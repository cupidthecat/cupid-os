# ADR 0204: Transfer installation-table generation to CupidObj

## Status

Accepted on 2026-08-01.

## Context

ADR 0201 gave CupidObj a typed operation for the bin, docs, and demos
installation-table formats. ADR 0203 promoted a checked seed that carries the
matching `install-source` command. The normal Make recipes still called
`tools/hostbuild.py`, so Python remained the code-producing owner for three
active `.cc` files between CupidObj packaging and CupidC compilation.

The transfer has to preserve Make's discovered path order and the exact source
bytes. It also has to keep the checked seed manifest, all five seed images,
and the checked runner in each recipe's dependency closure. Running an
unverified native CupidObj command would bypass that trust boundary.

## Decision

The normal Make graph now generates these sources with the checked CupidObj
seed:

| Output | Command |
| --- | --- |
| `kernel/util/bin_programs_gen.cc` | `$(CUPIDOBJ) install-source bin` with the bin, header, and browser inventories |
| `kernel/util/docs_programs_gen.cc` | `$(CUPIDOBJ) install-source docs` with the CTXT, docs-asset, and home-asset inventories |
| `kernel/util/demos_programs_gen.cc` | `$(CUPIDOBJ) install-source demos` with the CupidASM demo inventory |

Each recipe depends on `$(CUPIDOBJ_INPUTS)`. That set contains the Makefile,
checked-seed runner, seed manifest, and all five checked images. The runner
verifies and freezes the trust unit before it invokes CupidObj, then checks
the live unit again after the command.

`tools/hostbuild.py` is no longer a prerequisite or production generator for
these outputs. It remains the byte-parity oracle and keeps its unrelated image,
fixture, symbol, staging, and cleanup work.

The active-source audit names all three transforms
`generate_install_source`. Their tool set is `cupid_object` plus
`host_python`: CupidObj owns the generated bytes, while Python launches the
checked i386 tool and remains part of the reachable transform. The delivery
guard fixes all three targets, their mode-specific recipes and inventory
markers, the shared operation and tool set, and every checked-seed input.

## Rejected alternatives

Keeping `tools/hostbuild.py` as the production generator was rejected because
the promoted CupidObj command already owns the format and matches every live
output.

Calling a native hosted CupidObj executable was rejected because the normal
graph must use the manifest-bound checked seed on Linux and through WSL on
Windows.

Removing Python from the transform's audit tools was rejected. Python still
verifies and launches the checked seed, even though it no longer constructs
the source bytes.

Deleting the Python generator modes was rejected because they remain useful
as independent byte-parity oracles.

## Consequences

CupidObj now owns production generation for all three installation tables,
and checked-seed CupidC continues to compile them under the fixed kernel
profile. Adding or removing a discovered program, header, browser fragment,
manual, asset, or demo still flows through Make's ordinal inventory.

The transfer removes three Python-owned source-generation operations without
removing Python from the build. Python still coordinates every checked-seed
launch and retains its other production, test, and packaging roles. The total
transform count therefore stays at 449 while CupidObj's reachable count rises
to 185.
