# ADR 0445: Pass reviewed behavior context to public bootstraps

Date: 2026-10-07

Status: Implemented privately; qualified cohort and complete public entry points accepted

The public bootstrap commands rebuild the current source, but their behavior
fixtures omit the explicit release required by current plans. The historical
reader must keep rejecting that missing authority. A reviewed release can
authorize the same tool bytes through the existing ADR 0418 reuse boundary.
A changed compiler still needs ADR 0426's separate preparation and qualification
flow before it can become the reviewed cohort.

Add optional `--seed-release` selection to the Linux and native Windows public
commands. Capture it after freezing the selected seeds. Native Windows retains
both execution and Linux plan roles, checks their complete paired identity and
revalidates both through publication. The request admits only the selected
format and exact reviewed plans. Every one of the six tools in both final
stages must match the reviewed artifact table. Producer source observations and
object comparisons remain the caller's original facts.

Omitting the option preserves the historical call shape and fixed-point
comparison. An explicit candidate `ReleaseRequest` and reviewed reuse selection
are mutually exclusive. Neither route relaxes the historical reader, parent
checks or executable import profiles.

Actual script and module entry points initially failed malformed-release
controls with an uncaught traceback. Python loaded the driver as `__main__`
and again under its package name, creating distinct `BootstrapError` classes.
The executable driver now registers its package name before importing the
coordinator. Both entry forms use one exception identity. Missing-file controls
then exposed raw filesystem errors at capture and final revalidation. The
reviewed behavior reader converts those failures to the existing bounded
bootstrap diagnostic. The selected output stays absent in each rejection.

The original five-module compatibility selection passes 500 executions with
eighteen platform skips. Its exact five inputs remain retained before the CLI
corrections. The current context module has 22 controls; native Windows passes
all of them. Independent rereading of the corrected five-module rerun checks
508 passes and twenty host skips across 528 selections. Its five raw inputs
remain retained before the subsequent seed-pin adoption. Retained
red and green subprocess controls cover malformed and missing releases on both
entry forms; native Windows also exercises the Windows command. Linux keeps
the explicit Windows-host skips.

The private Make recipes and complete fixed-point test select the installed
release. The original older cohort could not authorize the changed emitter.
The committed replacement now passes independent paired qualification and is
installed privately under ADR 0446. Both actual public Make recipes now pass;
independent rereading checks all 291 staged products and 7,761 published files.
The corrected complete selections also pass: three executed methods and Linux's
declared Windows-method skip across four selections. The native Windows run
retains the complete long/alias preparation and unreleased-parent rejection.
Both fresh OS builds pass paired independent review and all four strict boots.
Linux external-user checks pass; Windows external ls retains an EHCI panic.
Ordinary and long-path SDK publications remain separate acceptance requirements.
After reviewed object-lock adoption, the same compatibility selection passes
508 executions with twenty expected skips. ADR 0446 records the preceding
stale-lock failures, paired object review and exact lock changes. Byte matching
stays strict. See
[the behavior context record](../bootstrap/BOOTSTRAP-BEHAVIOR-CONTEXT.md).
