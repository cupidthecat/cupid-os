# ADR 0369: Add typed kernel-symbol publication to CupidBuild

## Status

Accepted

## Context

The normal kernel build derives `kernel/cpu/ksyms_data.cc` from the pass-one
kernel ELF. Host Python currently freezes the pass-one image and promoted seed,
runs CupidDis `-n`, builds an independent KSYM oracle, asks CupidObj to emit the
source, compares both results, and publishes the source atomically.

The generic CupidBuild runner cannot replace that boundary. It forwards a
tool's output to the caller and does not retain the output as a pinned input for
a second tool. It also has no independent understanding of the KSYM format.
Moving only the two tool launches would lose the parity check that can veto a
bad producer.

## Decision

Source-head CupidBuild provides this typed command:

```text
cupidbuild generate-ksyms \
  --seed-manifest MANIFEST \
  --root ROOT \
  --source SOURCE \
  --output OUTPUT
```

The operation opens the existing guarded artifact transaction and freezes the
pass-one ELF, seed manifest, and all six promoted tools. CupidBuild runs frozen
CupidDis with standard output directed to the transaction's private auxiliary
file. Shell redirection is not involved. Successful inspection requires empty
standard error and a bounded regular output.

CupidBuild then parses the captured symbol rows itself. The parser accepts the
same text and weak symbol classes as CupidObj, rejects malformed or out-of-range
addresses, excludes `.L` names, sorts by address while retaining source order,
and keeps the first name at a repeated address. Its renderer constructs the
little-endian `KSYM` header, address and string-offset rows, NUL-terminated name
table, four-byte padding, and exact word-packed `.cc` spelling.

Frozen CupidObj receives the same captured rows through `ksyms-source` and
writes the private candidate. CupidBuild requires an exact byte match with its
independent rendering. It rechecks the live seed, source, captured rows,
candidate, lock, destination, and pinned output parent before atomic
publication. A tool failure, parity failure, drift, or lock conflict preserves
the previous destination.

The renderer deliberately retains the historical
`Auto-generated by tools/hostbuild.py` banner for this source-capability step.
The active promoted CupidObj images emit those bytes. Changing the banner now
would reject otherwise valid output before a new seed pair can carry both sides
of the format change. Attribution can be corrected in a later paired promotion
without weakening parity.

The source-head fixed-point behavior matrix now includes one successful
kernel-symbol generation and one malformed-ELF rollback on Linux and native
Windows. Linux uses an ELF from its checked seed. Native Windows uses the paired
Linux plan seed as the ELF fixture, while the Windows seed supplies the running
CupidDis and CupidObj images.

The Linux fixed point passed with 22 C objects, one startup object, all six
tool images, and the 27/6/34 behavior matrix equal between stages three and
four. Its 51,567-byte report has SHA-256
`d94e1f8908bbecb9331a6e6b20c007b64f24a5b6b18b1f2562d000973402d2c2`.
The final source-head CupidBuild image is 340,548 bytes with SHA-256
`b83daf1d4e37739501c56045da30a035477d539bbf20f13994c7c8ada0781b01`.

The native Windows fixed point also passed. It matched 23 C objects, three
assembly objects, and all six PE32 tools between stages three and four, then
completed the 16/6/21 behavior matrix. Its 64,673-byte report has SHA-256
`1eb9a1d1f0572a226436afcc2e6cde033a39e8466799a6e4f636a09f02b83ab0`.
The final 355,328-byte CupidBuild image has SHA-256
`3ec41c553ee26e37ed1153a13cf666c0ae5de860f92a7f18279c2943046f7588`.

The final hosted public-seam module passed all 86 tests in 69.195 seconds,
with three expected platform skips. Its negative coverage executes malformed
symbol-row rejection and an exact parity mismatch from a valid, deliberately
altered CupidObj image; both prove destination rollback. The
documentation-bearing OS then passed the full 83-root build, both kernel
links, strict whole-image inspection, all 16 artifact rows, and a private
four-vCPU E1000 smoke with strong SMP verification and `/bin/ls.cc`.

## Consequences

CupidBuild can own the complete kernel-symbol publication contract in source,
including the safety properties that previously surrounded CupidDis and
CupidObj in Python. The normal Make recipe remains on Hostbuild until paired
Linux and Windows seed promotion carries the new command. Production graph
ownership therefore stays at 193 CupidBuild and 259 Python participations, with
five composite Python-coordinated CupidObj paths still present.

The new host adapter operation is intentionally narrow. It captures one checked
tool's standard output as the existing private auxiliary artifact and does not
turn arbitrary pipelines into a public interface. Existing artifact operations
keep their 64 MiB file limit and sixteen-input ceiling.

No active source is simplified or renamed. The remaining tracked `.c` files are
fixtures or reference inputs rather than CupidC-owned active translation units,
so this change creates no valid `.c` to `.cc` rename.
