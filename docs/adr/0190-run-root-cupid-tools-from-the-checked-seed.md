# ADR 0190: Run root Cupid tools from the checked seed

## Status

Accepted on 2026-07-30.

ADR 0196 supersedes this record's statements that `toolchain:all` still needs
GCC, Clang, or a host linker. The normal Toolchain cohort now uses the checked
seed and staged Cupid-built tools. Native builds remain explicit oracles.

## Context

The root image already used CupidASM, CupidObj, CupidLD, and CupidDis for every
production assembly, object, link, and inspection transform. It still prepared
native hosted copies of those four commands before doing that work. A clean
root build therefore needed GCC or Clang, the host C runtime, and the host
linker even though the repository carried a checked static i386 Linux seed
with the same tools.

The command variables also served as Make prerequisites. Replacing an
executable path with a multiword Python command would have made that dual use
invalid. Symbol generation and JPEG embedding added two more seams because
`hostbuild.py` launched one executable path directly.

## Decision

The normal root graph runs CupidASM, CupidObj, CupidLD, and CupidDis from the
checked five-tool seed. Each invocation verifies the manifest, freezes all five
seed images as one trust unit, and executes the selected private image. After
the command returns, the runner verifies the live manifest and all five images
again. A command cannot succeed after its trust unit changes. Linux runs the
static i386 command directly. Windows uses WSL.

Make command variables and dependency closures are separate. The default
closures contain the manifest, all five seed images, the runner, and the
Makefile. A manifest override moves the complete closure to the new manifest
directory. Explicit command overrides can provide their own input closure.
Every wildcard-discovered list that affects generated bytes or link order
passes through Make's `$(sort ...)`, so host locale cannot reorder the root
cohort.

Kernel-symbol generation calls checked CupidDis through the same runner
against a frozen pass-one kernel. JPEG embedding accepts only a well-formed
sequential SOF0 or SOF1 frame, copies its bytes unchanged, and asks checked
CupidObj to wrap that exact snapshot. Progressive, unsupported, and malformed
JPEG input fails before object publication. Both nested paths keep an existing
output if the tool fails or an input changes during the operation.

Native hosted tool targets remain available for development and oracle work,
but root `all` cannot reach them.

## Evidence

The checked runner has positive coverage against the real CupidASM seed. Its
negative cases cover a changed seed before execution, live cohort drift while
the private command runs, invalid tool requests, timeouts, and exact nonzero
status and stream forwarding. The complete checked-seed suite passes 32 tests
in 701.652 seconds.

Hostbuild tests cover checked CupidDis and CupidObj success, tool failure,
input drift, output preservation, exact JPEG copying, and rejection of
progressive or malformed frames. All 24 tests pass in 2.989 seconds.

The regenerated graph contains 500 transforms. Root `all` has 438, `user:all`
has eight, and `toolchain:all` has 54. Root ownership includes four CupidASM
transforms, 182 CupidObj transforms, two CupidLD transforms, one CupidDis
transform, and 242 CupidC transforms. No recursive Make transform remains.
Across all three roots, Python participates in 448 transforms and the hosted
Toolchain retains all 52 host C transforms.

The focused graph suite passes all 67 cases in 507.408 seconds. It covers the
checked trust unit, command overrides, nested tool attribution, direct root
ownership, and locale-neutral source discovery.

A forced root build with the conventional compiler, assembler, linker,
symbol-reader, and object-copy variables poisoned reached the ISO fixture
authoring step. That separate step still needs an external ISO author when the
fixture must be regenerated. After retaining the unchanged fixture, the
complete poisoned root build passed in 378.1 seconds.

The first Windows and Linux kernel-artifact comparison matched 426 of 430
files. The remaining four were the wrapped JPEG object, both linked ELF
passes, and the raw kernel. The generated source tables already matched after
Make sorting. The differing object came from host FFmpeg processing of the
tracked progressive JPEG, and the Windows and Linux encoder builds produced
different bytes.

The repository now stores the same baseline JPEG bytes that the accepted
Windows path had produced. Build-time JPEG handling validates and copies those
bytes without calling FFmpeg, `jpegtran`, `djpeg`, or `cjpeg`. Checked CupidObj
then wraps the byte-exact snapshot. The Linux
`make -j8 kernel/kernel.bin WAD_SRCS=` build passed in 607.7 seconds. Windows
`make -j8 all WAD_SRCS=` passed in 341.6 seconds. All 430 frozen kernel
artifacts match byte for byte.

## Rejected alternatives

Keeping the hosted executables in root `all` was rejected because it retained
a host code generator for commands already present in the checked seed.

Using one variable as both a command and a prerequisite was rejected because a
multiword checked runner is not a filesystem input.

Copying only a Python launcher into the nested symbol and JPEG operations was
rejected because the launcher does not contain the manifest-bound executable
trust unit.

Caching a mutable shared seed directory was deferred. The current private
snapshot is slower, but it has simple per-command integrity and concurrency
rules.

Normalizing a progressive JPEG during each build was rejected. The available
host encoder changed the embedded bytes across Windows and Linux. Copying the
old progressive input unchanged was also unsuitable because Cupid OS accepts
sequential SOF0 and SOF1 frames, not progressive SOF2 frames.

## Consequences

GCC, Clang, a host assembler, and a host linker are no longer prerequisites of
root `all`. They remain prerequisites of `toolchain:all` and explicit native
oracle targets.

The normal build no longer needs FFmpeg, `jpegtran`, `djpeg`, or `cjpeg` for
its JPEG object. It still needs Python. Windows also needs WSL to execute the
static i386 Linux seed. The checked tools are not yet native Windows commands,
and the hosted contract/tool build is not yet self-hosted.

Every root transform now pays for a private manifest verification and seed
snapshot. A future cache may reduce that cost only if it stays immutable,
parallel-safe, and manifest-verified.
