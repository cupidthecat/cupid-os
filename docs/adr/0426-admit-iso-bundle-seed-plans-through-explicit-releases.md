# ADR 0426: Admit ISO bundle seed plans through explicit releases

The ISO request codec adds a thirtieth C source to the current Linux plan and
an eighth object to the CupidObj link. The shared manifest reader must recognize
that complete plan while preserving ADR 0411's separate authority for new
parents. Current plan support therefore requires an explicit release record;
the historical entry point keeps its existing parent and plan rules.

The source capability passes native and Cupid-built caller checks on both
hosts. Both stage preparations pass independent checks. Separate release
authoring passes. Windows rebuilt behavior qualification passes; Linux
qualification remains incomplete.

## Contract

The reader recognizes five current Windows profiles: ANSI, UTF-8, long paths,
directory aliases, and long paths with aliases. Their source counts are 80, 85,
86, 86 and 87. Each profile binds both exact plan digests and its import table.
The two 86-input profiles remain distinct. Linux accepts the current plan with
the corresponding complete captured source counts. These counts identify
supported plan shapes; they do not authorize a parent tuple.

Every current profile requires the exact codec source name and path, its
ordinary source flag, all existing sources and links, and the ordered CupidObj
link containing the codec. The release must match the manifest's source,
parent, plan and artifact claims before structural validation. A matching
record cannot authorize an unknown count or plan. The existing pair reader
still binds Windows' Linux-manifest reference to actual manifest bytes.

New parents come only from the explicitly selected external record. No
finished parent-manifest hash is added to C source. Neither the record nor a
successful byte API call establishes independent review, immutable file
lifetime, staged behavior qualification or permission to promote a seed.

## Evidence

The 69-method native manifest/release selection passes on each host. The new
twelve-method profile suite also passes with actual Cupid-built PE32 and ELF32
callers: 162 executions across these selections, with no skips. Cases cover
all five profiles, reordered fields, exact count/plan bindings, changed parent
members, codec source and link corruption, unrelated link drift, unknown
profiles with matching records, cleared failure results, bounded diagnostics,
input preservation and recovery. Strict calls reject the new profiles both
before and after release-aware calls.

The retained old reader fails nine of the twelve new methods on each host.
Checked CupidC compiles the current reader and contract on both platforms;
their object pairs are identical. The reader object is 96,832 bytes with
SHA-256 b857af3faebf4cf279a0cb3771b9be7f9fdaf023ee5d89ae5cc2e94f6f1d6f1d;
the caller is 6,380 bytes with SHA-256
c94d85bfe988ee36e7606f92b1ea6385dfe0a9151aa4d2729f0be4be149e2bfc.
CupidDis certifies the objects and CupidLD links both hosted callers.

Independent evidence is `checked-iso-seed-profiles-paired-independent.json`
under `cupid-native-iso-proof-20261005`. It rereads current sources, retained
support, tool identities, actual commands, complete method logs, object pairs
and unchanged installed seeds. This receipt qualifies the reader capability.
It does not qualify a fresh tool publication.

## Failed approaches and remaining work

The retained ordinary Windows bootstrap rejects the current profile at strict
provenance validation. Private one-variable probes show that changing counts
and plan hashes alone leaves that rejection intact; embedding the current
parent tuple then admits the request. That last private probe conflicts with
ADR 0411 and remains diagnostic evidence only. The production reader instead
requires the separate release-aware path. The earlier Linux bootstrap also
retains its stage-four frontend timeout; it is not a completed fixed point.

The first checked caller used `atoi`, which the checked hosted interface does
not provide. Both compilers rejected it. The caller now parses its three
bounded decimal control arguments directly; runtime and compiler interfaces
are unchanged. The first release-aware parent mutation was identical to the
selected historical tuple, so the fixture now changes an actual tuple member.
Original failed logs and private probe artifacts remain retained.

Both long-path/alias preparations pass and retain the same 87-input closure.
Independent checks reread 174 source copies and 249 stage artifacts, validate
object/image formats and confirm 83 stage-three/stage-four pairs. Separate
authoring matches all twelve tools. The release candidate is 2,736 bytes with
SHA-256 66f714e0cf43c4d82ca97b93bd6ed3c070a6d1d5488f81a5333ca51a2247df1d.
The original preparations keep status `unqualified`. A separate Windows
qualification rebuilds all three stages and passes seven help, sixty success
and fifty-four failure groups in each final stage. Independent rereading checks
138 stage artifacts, 87 source copies, 46 final-stage pairs and 100 equal
behavior product pairs. Its working-source receipt is
`iso-windows-release-qualification-independent.json`; it does not establish
committed-source qualification, the later 528-input change or seed installation.
Linux's first qualification is interrupted by a WSL restart and
has no closed result. Its complete verified preparation copy remains intact
and is copied into a new native source control. The restart cause is unproven.
The initial collector chose output outside the source root;
both coordinators rejected it before building. Corrected collectors keep
output under the root without changing that boundary.

The 158,896-byte profile manual passes installed-seed kernel/image acceptance
and a strict private four-CPU max/e1000 boot with completed `ls` and SMP
checks. Independent proof rereads all 429 objects and sixteen artifacts,
finds only its wrapper changed and preserves FAT data. Its raw kernel is
9,591,684 bytes. This uses installed tools and keeps staged qualification
separate. Evidence is `manual-independent-windows.json` under
`cupid-native-iso-profile-manual-20261005`.

Guarded ISO publication, seed installation, SDK integration and the normal
recipe handoff remain open. Normal ownership remains 447 CupidBuild and five
Python actions across 452 transforms. New sources use `.cc`; `TempleOS/`
remains read-only reference material and is excluded from these counts.
