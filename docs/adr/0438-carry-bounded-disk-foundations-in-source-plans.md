# ADR 0438: Carry bounded disk foundations in source plans

## Status

Implemented and tested privately on 2026-10-06. Candidate plans and native and
Cupid-built readers and Python coordinator controls pass on both hosts.
Paired producer qualification and seed installation remain open.

## Context

The bounded FAT16 writer, Unicode name profiles and disk composer pass their
native and Cupid-built contracts. Wide file positioning, streamed retained
observations and digest-only transaction snapshots also pass their focused
runtime gates. The producer plans still describe the earlier ISO publisher.
Carrying these foundations requires complete source capture and explicit
reader profiles before a new tool cohort can qualify.

## Decision

Add fat16_stage, fat16_names and disk_image to the candidate C sources and
CupidBuild link. The plan contains 37 Linux C sources, 38 objects and 23
CupidBuild link members. Capture fat16_name_profiles.inc explicitly whenever
the name module participates. All three sources retain standard Cupid C mode.

Keep the installed parent's 34-source and 20-link promotion constants until
a replacement cohort qualifies. Extend the C seed reader with five additional
exact source-count and Windows plan profiles, preserving every historical
profile and release requirement. Bind the new Linux plan to the three module
sources and exact link order. An overlapping input count cannot substitute an
older plan hash.

The SDK source/control inventory and compiler producer closure remain separate.
The SDK captures 104 inputs: the previous 101 plus three headers. The bootstrap
captures the three source/header pairs and Unicode table, giving 97, 98, 98 or
99 inputs across its Windows selections. Extend the native author and verifier
with explicit 37-source, 38-object profiles and compare all three additional
raw object pairs. Captured requests may use the corresponding 100-input
inventory without release controls or the complete 104-input inventory;
classic requests cannot authorize either extension. Preserve the historical
92-, 96-, 97- and 101-input inventories.

Add the three objects and their real source dependencies to the optional host
Make build. The Unicode table is a name-module compilation prerequisite.
